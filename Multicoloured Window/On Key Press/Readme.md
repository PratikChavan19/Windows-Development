# Multicoloured Window – On Key Press 🎨🪟

A **Win32 API application written in C** that changes the window's background color based on the key pressed by the user.

This project demonstrates **keyboard event handling, Windows messages, GDI brushes, window repainting, and event-driven programming** using the native Windows API.

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

## 📌 About the Project

The application creates a native Windows window and allows the user to change its background color by pressing specific keyboard keys.

Each supported key is mapped to a different color:

| Key                 | Color            |
| ------------------- | ---------------- |
| `R` / `r`           | 🔴 Red           |
| `G` / `g`           | 🟢 Green         |
| `B` / `b`           | 🔵 Blue          |
| `C` / `c`           | 🩵 Cyan          |
| `M` / `m`           | 🩷 Magenta       |
| `Y` / `y`           | 🟡 Yellow        |
| `O` / `o`           | 🟠 Orange        |
| `V` / `v`           | 🟣 Violet        |
| `W` / `w`           | ⚪ White          |
| Any other character | ⚫ Black          |
| `ESC`               | Exit application |

## The color selection is stored in `chColorFlag`, and the window is repainted whenever a character key is received.

## ⚙️ How It Works

The application follows the standard Win32 application lifecycle.

### 1. Window Initialization

The application starts from `WinMain()` and initializes a `WNDCLASSEX` structure.

The window procedure is registered through:

```c
myWindowClass.lpfnWndProc = WndProc;
```

The window class is then registered using:

```c
RegisterClassEx(&myWindowClass);
```

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

### 2. Window Creation

The application creates the window using:

```c
CreateWindow(...)
```

It then displays and updates the window using:

```c
ShowWindow(hwnd, iCmdShow);
UpdateWindow(hwnd);
```

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

### 3. Message Loop

The application continuously processes Windows messages through the standard message loop:

```c
while (GetMessage(&msg, NULL, 0, 0))
{
    TranslateMessage(&msg);
    DispatchMessage(&msg);
}
```

Messages are eventually dispatched to the `WndProc()` callback function.

## 🎨 Color Handling

The main functionality is implemented inside `WM_PAINT`.

A solid GDI brush is created based on the value of `chColorFlag`.

For example:

```c
case 'R':
case 'r':
    hBrush = CreateSolidBrush(RGB(255, 0, 0));
    break;
```

Similarly, different RGB values are used for the other supported colors.

The complete color mapping is:

```text
R/r → Red
G/g → Green
B/b → Blue
C/c → Cyan
M/m → Magenta
Y/y → Yellow
O/o → Orange
V/v → Violet
W/w → White
Other → Black
```

## ⌨️ Keyboard Input

The application uses two Windows messages for keyboard handling:

### `WM_KEYDOWN`

`WM_KEYDOWN` handles physical key presses.

The `ESC` key is specifically handled to close the application:

```c
case VK_ESCAPE:
    DestroyWindow(hwnd);
    break;
```

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

### `WM_CHAR`

`WM_CHAR` receives the character generated by the keyboard input.

The pressed character is stored in:

```c
chColorFlag = wParam;
```

The application then explicitly requests a repaint:

```c
InvalidateRect(hwnd, NULL, TRUE);
```

This causes Windows to generate a `WM_PAINT` message so that the new background color can be rendered.

-------------------------------------------------------------------------------------------------------------------------------------------------------------------

## 🖌️ Painting the Window

During `WM_PAINT`, the application:

1. Gets the client area using `GetClientRect()`.
2. Starts the painting operation using `BeginPaint()`.
3. Creates a brush based on the selected color.
4. Selects the brush.
5. Fills the client area using `FillRect()`.
6. Deletes the brush using `DeleteObject()`.
7. Ends the painting operation using `EndPaint()`.

The client area is filled with the selected brush color.

The basic flow of the application is:

```text
        ┌──────────────────┐
        │   User presses   │
        │       key        │

                 │

                 │
                 ▼

          │   WM_PAINT   │
          └──────┬───────┘
                 │
                 ▼
       Create color-specific
             GDI brush
                 │
                 ▼
            FillRect()
                 │
                 ▼
       Background changes
```

## 🧹 GDI Resource Management

The application explicitly releases the GDI brush after painting:

```c
if (hBrush)
{
    DeleteObject(hBrush);
    hBrush = NULL;
}
```

The device context is also released after painting with:

```c
EndPaint(hwnd, &ps);
```

This demonstrates basic **GDI resource management** in Win32 programming.
